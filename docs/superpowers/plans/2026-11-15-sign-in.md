# Sign-in Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitHub and Google sign-in with private per-user data, an invite-only tutor and account
deletion, replacing the shared dev user on the live site.

**Architecture:** A new `auth` module runs the OAuth flow (state + PKCE), issues its own short-lived
JWT access tokens and rotating refresh tokens, and `current_user` verifies the JWT in `AUTH_MODE=jwt`
(dev mode is unchanged). Angular keeps the access token in memory and the refresh token in
`localStorage`, attaches the token with an interceptor, refreshes once on expiry, and guards every
page behind `/signin`.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, Alembic, PyJWT, httpx; Angular 22 (signals, functional
interceptors and guards), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-14-sign-in-design.md`

## Global Constraints

- Access token: JWT HS256 signed with `JWT_SECRET`, 15 minutes, claims `sub`, `iat`, `exp`, `iss`,
  `aud`; reject unsigned tokens (`alg: none`) and other algorithms. `iss = "cortex-api"`,
  `aud = "cortex-web"`.
- Refresh token: random (`secrets.token_urlsafe(32)`), 30 days, only its SHA-256 hash stored;
  rotated on every use; reuse after rotation revokes the family, except within a 10-second grace
  window, which returns the same successor.
- OAuth state: random, single use, expires in 10 minutes, PKCE (S256) for both providers.
- Login code: random, single use, expires in 60 seconds, only its hash stored. The callback
  redirects to `{FRONTEND_URL}/auth/done#code=...`. Tokens never appear in a URL.
- Redirects only to the configured `FRONTEND_URL`. Errors use the existing one-JSON-error shape.
- Linking: a new identity joins an existing user only when both emails are verified and equal.
- Tutor: in `jwt` mode only users with a verified email in `TUTOR_INVITED_EMAILS` may use it;
  others get `403 tutor_not_invited` before anything is saved or Claude is called. The daily limit
  still applies. In `dev` mode the tutor works as today.
- `AUTH_MODE=dev` keeps working exactly as today. In `jwt` mode the API refuses to start without a
  `JWT_SECRET` of at least 32 bytes, a `FRONTEND_URL`, and at least one configured provider.
- Secrets only in environment variables; add names (never values) to `backend/.env.example`.
- Repo rules from `CLAUDE.md`: TDD, ruff line 100, mypy strict, 90% coverage, OnPush + signals,
  style budget 6 kB, every user table filtered by `user_id`. Commit only when Aayush says so;
  never stage `frontend/angular.json`. Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Two tabs refresh at the same moment with the same refresh token → both get a working pair (grace
   window), nobody is signed out. Test in Task 4.
   Also in Task 6: two tabs in one browser share `localStorage`, so after one tab rotates the token
   the other must read the new value before refreshing (test: refresh reads `cortex.refresh` fresh).
2. A refresh token is replayed after the grace window (stolen token) → the whole family is revoked
   and both holders must sign in again. Test in Task 4.
3. A GitHub user with no verified public email signs in → an account is created with
   `email = NULL`, it never links to another account, and the tutor refuses with
   `tutor_not_invited`. Tests in Tasks 4 and 5.
4. The user presses "Cancel" at GitHub (`?error=access_denied`) or replays an old callback URL →
   redirect to `/signin?error=cancelled` or `/signin?error=expired`, never a 500. Test in Task 4.
5. The access token expires while the tutor is streaming a reply or while "Download my data" is
   clicked → the request refreshes once and succeeds; neither silently fails as signed out.
   Tests in Task 6.

**Interfaces:**
- Consumes: Task 1 token functions, Task 2 models, Task 3 `OAuthProvider`/`Profile`.
- Produces endpoints (all under `/api/v1/auth`):
  - `GET /providers` → `{"mode": "dev" | "jwt", "providers": ["github", ...]}`
  - `GET /{provider}/start` → 302 to the provider; unknown or unconfigured provider → 404
    `provider_not_available`.
  - `GET /{provider}/callback?code&state` (or `?error`) → 302 to
    `{FRONTEND_URL}/auth/done#code=...`, or `{FRONTEND_URL}/signin?error=cancelled|expired|failed`.
    The redirect URI sent to providers is `{FRONTEND_URL}/api/v1/auth/{provider}/callback`.
  - `POST /token {code}` → `{"access_token", "refresh_token", "expires_in": 900}`; bad, used or
    expired code → 400 `login_expired`.
  - `POST /refresh {refresh_token}` → new pair; invalid/expired/revoked → 401 `refresh_invalid`.
  - `POST /logout {refresh_token}` → 204, revokes the family.
- `AuthService.sign_in(profile: Profile) -> User` implements the spec's linking rule and updates
  `display_name`, `avatar_url`, `last_login_at`.
